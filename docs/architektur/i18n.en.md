# Multiple languages

EDChar is available in English and German. English (`en_GB`) is the default, German (`de_DE`) can be chosen in the user account.

## In the app

- **Translations as resource files:** all texts of the user interface are in two ARB files, one per language, with 934 keys each (counted, 2026-11-19). Flutter generates the access class from them.
- **Choice of language:** the user chooses the language in the user account. The app remembers the choice in the browser's local storage and uses it at the next start.
- **British English as default:** `en_GB` instead of `en_US`, so that date pickers start the week on Monday.
- **Database content is not translated:** names and descriptions of talents, spells, disciplines and other game content come from the database and appear as stored.

## In the API

The app sends its language with every API call in the `Accept-Language` header. The API translates its messages to the app accordingly:

- If the first language in the header starts with `de`, messages are German; otherwise English.
- Without the header, messages stay as they are, so older clients see the previous behaviour.
- Error messages are translated automatically when they are sent. Technical messages without a translation, mostly about missing parameters, stay unchanged.

## Known gaps

Some texts in the app are still built into the code in English instead of coming from the resource files, and a few German terms are inconsistent. They were reported to the frontend instance in ticket 242.
